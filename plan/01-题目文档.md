## 1. 介绍

流程挖掘（Process Mining）是学术界成熟多年的领域：给定一份事件日志（每行 = 某个 case 在某时刻做了某活动），可以确定性推导出流程模型。工业界有 PM4Py、ProM、Celonis 等实现，但它们要么是重型 Python 库、要么是商用 SaaS——**没有任何一个以 Agent Skill 的形态存在**。

本题要求做一个流程发现图（Process Discovery Graph）Skill：输入事件日志，输出可直接在浏览器打开的交互式单文件 HTML，包含 DFG（Directly-Follows Graph，直接跟随图）、变体分析、瓶颈定位与符合度评分。核心卖点是**计算语义**：

- DFG 边频次 = 日志精确计数，可用 groupby 断言独立重算；
- 变体 = 按 case_id 分组排序后活动序列的可核对枚举，top-N 占比可精确验算；
- fitness = token replay 的确定性输出，纯算法；
- 布局 = 确定性分层布局，同输入同输出。

### 差异化（必须写清）

当前 agent skill 生态中，视觉类 skill 赛道已经拥挤，但它们占据的是"**渲染语义**"——把已有数据画得好看。本题卖的是"**计算语义**"：DFG 频次是日志精确计数、变体是可核对的枚举、fitness 是 token replay 的确定性输出。与最接近的弱竞品 retentioneering（933★，2019）的区别：它是点击流（clickstream）分析的 Python 库，不是流程发现图 skill，更不是 Agent Skill。

### 模型分工（表达层 vs 计算层）

- **模型只做表达层**：活动名语义归并建议（如 "Approve" / "Approved" 是否合并）、异常变体的自然语言解释、HTML 视觉风格。
- **模型永不产出频次、fitness、布局坐标**——这些全部由确定性代码计算。

## 2. 任务要求（首期模块 4-5 个）

### 模块①：SKILL.md 主入口 + 事件日志输入 schema

- **输入**：用户事件日志，CSV 或 JSON，三列/三字段：`case_id, activity, timestamp`。
- **输出**：SKILL.md 主入口（触发条件、工作流步骤、调用指引），日志校验器（列完整性、时间戳可解析、case_id 非空）。
- **确定性纪律**：schema 校验是纯规则判断，逐行报错行号，不允许模型"看一眼觉得没问题"。

### 模块②：DFG 与变体挖掘（精确计数 + 枚举）

- **输入**：通过校验的事件日志。
- **输出**：DFG JSON（节点=activity 集合，边=直接跟随关系及频次）+ 变体表（每个变体的活动序列、出现 case 数、占比、Top-N 排名）。
- **确定性纪律**：DFG 由日志精确计数（一条 groupby 断言即可重算）；变体 = 按 case_id 分组、组内按 timestamp 排序后活动序列去重计数；Top-N 变体频次占比必须精确到可手工核对。全部纯 Python/JS 标准库实现，禁止引入 PM4Py/NetworkX 等三方依赖。

### 模块③：瓶颈与统计

- **输入**：事件日志 + DFG。
- **输出**：相邻活动耗时统计（每条 DFG 边的 中位数 / P95 等待时长）、案例时长分布（min/中位数/P95/max）。
- **确定性纪律**：纯统计计算，所有数字可对同一份日志重算；瓶颈点位定义为耗时中位数排名靠前的边，规则固定、不得由模型主观指认。

### 模块④：单文件 HTML 渲染（确定性布局，零 CDN）

- **输入**：DFG JSON、变体表、瓶颈统计。
- **输出**：单文件 HTML——DFG 交互式网络图（节点=活动，边宽=频次，悬停/点击展开细节）+ 变体热力条（Top-N 变体占比条形视图），零 CDN、零外部请求，可直接双击打开。
- **确定性纪律**：布局用确定性分层布局（Sugiyama 类）或固定随机种子的力导向，**同输入同输出**——同一份日志两次渲染，节点坐标逐像素一致。断言写入校验器。

### 模块⑤：校验器与真值基准

- **输入**：合成事件日志（自带程序化植入真值）。
- **输出**：schema 校验 + 断言套件——频次可重算（"边频次总和 = trace 长度总和 − case 数"这类恒等断言）、变体枚举可核对（合成日志按构造已知全部变体）、瓶颈点位与已知真值比对。合成日志用虚构业务场景白名单（如"报销审批（虚构）"）。
- **确定性纪律**：真值由生成日志的程序同时输出，绝不手抄数字；所有断言在 CI/脚本中一条命令跑完。

### 扩展项（首期不做，留作 M6 之后）

- token replay fitness 完整实现（首期可只做简化版或留接口）；
- 时间线动画回放（事件按时间轴回放染色）;
- PM4Py 互导（导出 XES / 导入 PM4Py 对象）;
- 完整 Petri net / alpha miner。

每个模块的"输入 / 输出 / 确定性纪律"即验收口径，缺一不算完成。

## 6. 边界与非目标

- **不做完整 process mining 套件**：alpha miner、Petri net 全家桶、conformance checking 全谱系留扩展项，首期只做 DFG + 变体 + 瓶颈 + 简化符合度。
- **不做日志采集**：日志由用户提供，本 skill 只消费不产生。
- **隐私红线**：事件日志可能含业务数据——**纯本地处理，零上传**，HTML 输出同样零外部请求；文档中明示"用户须自行确认日志可被处理"。
- **品牌隔离**：不冒用 PM4Py/Celonis/ProM 商标，比较性表述仅作事实引用；仓库名与 Skill 名不包含第三方品牌词。
- **首期范围限定**：只承诺上述模块①-⑤；扩展项出现在 roadmap 中但不算交付物。
