# plan/03 模块详设（plan/00 里程碑 M1–M6 × 题面模块①–⑤）

每个模块的"输入/输出/确定性纪律"以题面为准（plan/01 §2），此处补实现级设计。**缺一不算完成**。

## M1 数据先行 → 题面模块⑤（生成器侧）

### tools/gen_synthetic_log.py
- 场景："报销审批（虚构）"白名单场景，活动词表含提交/主管审批/财务复核/打款/驳回/撤回等。
- 确定性 RNG：splitmix64 自研（禁 stdlib random），固定 seed，CLI `--seed`。
- 产出（全部落 `data/synthetic/`，冻结禁手改）：
  1. `events.csv` — 事件日志（case_id, activity, timestamp ISO 8601）；
  2. `events_variants.json` — 第二形态日志（JSON 数组），与 CSV **同内容双形态**（校验器双通路测试用）；
  3. `truth.json` — 程序化真值：DFG 边频次全集、变体全集（序列+case 数+占比）、Top-N 排名、瓶颈边真值（按耗时中位数排名）、案例时长分布；
  4. `manifest.json` — sha256 台账 + 行数/边数/变体数计数（生成器实算，非手填）。
- 真值纪律：**真值只存输入与期望**，期望可由输入独立复算（真值文件禁出现 `observed` 字段）；恒等式"边频次总和 = trace 长度总和 − case 数"由生成器自身断言。
- 埋点设计：故意植入长等待边（如"财务复核→打款"中位等待显著大）与罕见变体，使瓶颈/Top-N 真值非平凡。
- `--check` 通路：重生成到临时目录与冻结产物逐字节比对（冻结产物 + 重生成结果两层都断言）。

## M2 挖掘算法 → 题面模块②③

### src/process_atlas/mining.py
- `load_events(path)`：CSV（`csv` 模块）/JSON 双通路，统一为 `Event(case_id, activity, timestamp)`（timestamp=`datetime`，带时区则统一 UTC；无时区按 naive 处理并在文档声明）。
- `mine_dfg(events)`：按 (case_id, timestamp, 原始行号) 稳定排序后取相邻对计数；**时间戳并列时的次序以源行号为 tie-break**（确定性口径，K 项）。
- `mine_variants(events)`：按 case 分组、组内按 timestamp 排序 → 活动序列 → `Counter`；Top-N 排序 = 频次降序、并列按序列字典序。
- `bottlenecks(events, dfg)`：每边等待时长 = 后继事件 timestamp − 前驱事件 timestamp（同 case 内相邻对）；输出中位数/P95（线性插值，自实现分位函数）；案例时长分布 min/中位数/P95/max。
- 输出 JSON schema：`{nodes, edges[{from,to,count,median_wait_s,p95_wait_s}], variants[{seq,count,ratio,rank}], case_stats}`，全部字段键排序、可独立重算。
- 符合度：首期做**简化 fitness**（理想重演度：trace 恰好命中某变体的 case 占比之加权和），token replay 留接口（扩展项），接口签名定稿不实现。

## M3 渲染 → 题面模块④

### src/process_atlas/layout.py + render.py
- `layout.py`：分层布局（Sugiyama 类简化版）——按活动在 DFG 中的拓扑层级分层（同层内按活动名字典序排布）；环处理 = 回边不参与层级计算（层级 = 最长路径层，按 Kahn 序）；坐标 = (层 × 固定层距, 层内序 × 固定间距)，全程无浮点随机项，坐标取整到整数像素。输出 `{activity: {x, y, layer}}`。
- `render.py`：单文件 HTML 模板（`string.Template`，无三方模板引擎），内嵌：
  - DFG 网络图（SVG）：节点=活动（含频次标签）、边宽∝频次、悬停显示中位等待/P95、点击高亮该活动相关变体；
  - 变体热力条：Top-N 变体占比横向条形视图（CSS 宽度=占比）；
  - 汇总统计卡（case 数/活动数/边数/变体数/fitness）。
- 零 CDN 硬断言 `assert_no_external_resources(html)` 在 render 出口常驻（禁 `http(s)://`、协议相对 `//src`、`<link>`/`<script src>` 外链），非仅测试期验一次。
- 双跑一致：同输入两次 `render` 逐字节一致（含 `build_hash`——由内容派生的版本标识，禁时钟/时间戳入 HTML）。

## M4 校验基准 → 题面模块①⑤（校验器侧）

### src/process_atlas/logio.py（schema 校验器）
- 列完整性（缺列/多列/空行）、timestamp 可解析、case_id/activity 非空；**逐行报错**：`line 12: timestamp not parseable: 'xxx'`，全部错误一次性收集后统一报出（非首错即停）；JSON 通路报错带数组下标。
- 坏文件路径 → 退出码 2；校验失败 → 退出码 2 并逐行列错误。

### 基准套件（tests/ + cli `selftest`）
- 恒等断言：边频次总和 = trace 长度总和 − case 数；
- 真值对账：mining 输出 vs `truth.json` 逐字段相等（全量实跑、逐样本点名，非只对汇总率）；
- 双跑一致：全管线（解析→挖掘→布局→渲染）两次运行产物逐字节一致；
- 探活（可证伪）：基准内嵌注入缺陷探针——跑同一套 check 必须报出差异（探活打消费处导入引用），`selftest` 对空目录返回失败（exit 非 0），防编排层空壳。
