## 2. 数据源可获取性

- **无外部数据依赖**：题目不提供、不下载任何真实事件日志；日志由用户自备（CSV/JSON：`case_id, activity, timestamp`）。
- 开发与验证使用**合成事件日志**，仓库内自足。

## 3. 合成数据纪律

- 合成日志使用**虚构业务场景白名单**（如"报销审批（虚构）"），场景名须带"（虚构）"后缀，不模仿任何真实公司流程名。
- **真值植入 = 程序化标注**：生成日志的程序同时输出已知真值——DFG 各边频次、变体全集与 Top-N 占比、瓶颈点位（耗时中位数排名靠前的边）。真值由代码派生，**严禁手抄数字**。
- 合成日志与真值文件在 M1 冻结入 `data/`，此后只读；如需改数据，另立版本并重跑全部断言。

## 4. 数值口径纪律

- 时间戳统一可解析格式（ISO 8601 为默认），校验器逐行报错。
- DFG 边频次恒等式：**边频次总和 = trace 长度总和 − case 数**（每条 trace 贡献 len−1 条直接跟随对）。
- 变体占比分母 = case 总数；Top-N 排名规则（频次降序、并列按序列字典序）在 SKILL.md 中明文固定。
- 瓶颈口径 = 相邻活动等待时长的中位数 / P95，分位算法（如线性插值）固定并在文档标注。
- 题面与文档**不写漂移硬数字**（星标数等随时间变化的数据一律随检索式+基准日成对出现）。
- 隐私红线：事件日志可能含业务数据，一切处理纯本地、零上传，HTML 输出零外部请求。
